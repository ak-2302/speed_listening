# 速聴トレーニング Web アプリ仕様書

作成日：2026-10-23

状態：機能仕様。音声の実装方式、配布条件、実機性能は未検証。

## 1. 目的と対象

日本語の文章を速い音声で繰り返し聞き、用意された教材では内容の理解度を確認する。視覚障害のないユーザーが PC またはスマートフォンのブラウザで GUI を操作することを想定する。文章を理解できたかを確認するためのアプリであり、トレーニングの効果を保証するものではない。

初期版は個人利用を想定する。アカウント、端末間同期、AI による問題生成、ユーザーが自分の文章に問題を追加する機能は対象外とする。

## 2. 利用の流れ

### 問題付き教材

1. 教材一覧から教材を選択し、タイトルと再生操作を確認する。
2. 再生速度を指定し、音声を生成して聞く。必要に応じて一時停止、シーク、繰り返し、速度変更を行う。
3. 聞き終えたら「問題に進む」を選び、教材に付属する選択式の問題に回答する。
4. 採点後に正答数と各問題の正解・解説を確認する。結果は同じブラウザに保存される。

### 自分の文章

1. テキストを入力または貼り付け、音声を生成して聞く。
2. 教材と同じ再生操作を使用する。理解度テストは提供しない。

## 3. 機能要件

### 3.1 教材と文章

- 教材一覧には少なくともタイトルを表示し、選択した教材の本文を音声化する。
- 教材は開発側が作成する。各教材は複数の選択式問題を持ち、本文・選択肢・正解・解説の整合性を確認して収録する。教材数は実装時に決定する。
- 自分の文章は入力欄で編集できる。空白のみの入力では音声を生成せず、理由を表示する。最大文字数は対応端末の実測後に決定し、決定した上限を入力時に表示する。
- 生成済みの音声と入力文が異なる場合は、古い音声であることを表示する。新しい文章を聞くには再生成する。
- 教材本文を画面で確認できるようにする。聞く前に答えが見えないよう、問題の正解・解説は採点後まで表示しない。

### 3.2 音声と再生

- NVDA 日本語版 2026.2jp の JTalk 初期音声である `tohoku-f01-neutral.htsvoice` と同じ音声データの使用を優先する。出所とライセンスは[配布元の説明](https://github.com/nvdajp/nvdajp/blob/release-2026.2jp/source/synthDrivers/jtalk/tohokuf01/README.md)を参照する。
- 同じ声を目標とし、NVDA の辞書、前処理、読み方や速度との完全一致は必須としない。違いは実聴比較して記録する。音声データの利用とブラウザ上での動作は実装・配布前に検証する。
- 文章から音声を生成し、再生、一時停止、再開、先頭へ移動、再生位置の変更、全体の繰り返しを可能にする。繰り返しの初期状態はオフとする。
- 速度の暫定仕様は **1.0〜4.0 倍、0.1 刻み、初期値 1.0 倍**。現在値を表示し、スライダーと数値入力で変更できる。再生中の変更も反映する。
- 速度範囲は PC とスマートフォンの実機で音が出ることと聞き取り可能性を確認した後に確定する。NVDA の高速読み上げと同じ速度や音質を保証しない。
- 通常速度で生成した音声の再生速度を変更し、音高を維持する方式を暫定候補とする。対応ブラウザや音質を実測して方式を確定する。
- 音声はユーザーの操作で再生を開始し、自動再生の拒否や再生失敗を検出して再試行を案内する。

### 3.3 理解度テスト

- 問題は教材に付属するものを使用する。音声を聞いた後にユーザーが「問題に進む」操作で開始する。再生終了を自動判定して出題を強制しない。
- 問題ごとに選択肢から一つを選ぶ。全問回答後に採点できる。未回答がある場合は採点せず、未回答であることを示す。
- 採点結果は正答数／問題数と、各問題の回答、正解、解説を表示する。教材を再度選び直して再挑戦できる。
- 本文は確認できるが、正解・解説は採点まで表示しない。教材の本文を読むかどうかはユーザーが選ぶ。

### 3.4 練習記録

- 問題付き教材の採点完了時に、教材 ID、実施日時、採点時に選択されていた再生速度、正答数、問題数を保存する。途中で速度を変更した場合の履歴は保存しない。
- 教材ごとに過去の結果を同じブラウザで確認できる。記録は端末内のブラウザストレージに保存し、別の端末やブラウザには同期しない。
- 入力本文、生成音声、各設問の回答は自動保存しない。ブラウザデータを消去すると保存した結果も失われることを示す。
- 保存が利用できない、または容量不足の場合は採点結果をその場で表示したうえで、保存できなかったことを知らせる。

## 4. 教材と記録のデータ

教材は開発側が管理する静的データとして配布する。形式の候補は JSON とし、下記を満たす。

| データ | 内容 |
| --- | --- |
| 教材 | 一意で安定した ID、タイトル、本文、問題の配列 |
| 問題 | 教材内で一意の ID、問題文、選択肢の配列、正解の選択肢 ID、解説 |
| 選択肢 | 問題内で一意の ID、表示文 |
| 練習結果 | 教材 ID、実施日時、採点時の速度、正答数、問題数 |

問題はそれぞれ複数の選択肢と正解を一つ持つ。開発時に ID の重複、空欄、正解が存在すること、および問題・解説と本文の整合性を確認する。教材 ID を変更・削除した場合の過去記録の扱いは、教材更新方法と合わせて実装時に決定する。

## 5. 画面・操作

- 主画面は教材の選択または文章入力、音声生成、再生、速度操作を順に配置する。教材テストと結果・履歴への導線を設ける。
- 主要情報は教材名、現在の再生位置、速度、生成状態、採点結果とする。装飾よりも聞く・答える操作の分かりやすさを優先する。
- PC とスマートフォンの両方で、文章入力、再生操作、テストへの移動が可能なレイアウトにする。
- 入力欄と速度・選択肢にはラベルを付け、キーボードでも操作可能にする。フォーカスを見えるようにし、状態を色だけで表さない。
- 初回の音声データ取得中、生成中、再生可能、失敗を区別する。生成中は重複生成を防ぎ、失敗時は原因と再試行方法を表示する。初回取得量は実測した値を表示する。

## 6. 技術とプライバシー

- フロントエンドは React + TypeScript + Vite を採用候補とし、静的ホスティングを想定する。
- 音声は Open JTalk + HTS Engine の WebAssembly と Worker によるブラウザ内合成を候補とする。ライブラリ、辞書、音声および前処理の具体的なバージョンは互換性と配布条件の確認後に固定する。
- ユーザーが入力した本文はサーバーや外部 AI に送信しない。音声データ等の取得に通信が必要な場合は、その旨を表示する。
- 初回のデータ取得には通信が必要。キャッシュの保持やオフライン利用は保証しない。
- 録音・音声ファイルのダウンロード、外部分析サービス、共有、ユーザー認証は初期版の対象外とする。

## 7. 受け入れ条件

以下は実装後の確認項目であり、仕様書作成時点ではいずれも未実施である。

1. PC とスマートフォンで、教材選択、音声生成・再生、問題への回答、採点、正解・解説の確認まで行える。
2. 任意の文章を入力して再生でき、空入力、文章変更後の古い音声、データ取得・生成・再生の失敗を判別できる。
3. 再生・一時停止・再開・先頭移動・シーク・速度変更・繰り返しが動作する。速度の上限は対象端末で実際に音を聞いて決める。
4. 教材の各問題が一つの正解を持ち、未回答時には採点されず、採点結果と解説が教材データと一致する。
5. 採点結果がブラウザ再訪後に教材別に確認でき、ストレージ失敗時は保存失敗を通知する。入力本文は自動保存されない。
6. 長文、狭い画面、キーボード操作、読み込み失敗、再生拒否を確認する。ユーザー入力が意図せず外部送信されないことをネットワーク通信で確認する。
7. 採用音声の出所・ハッシュ・ライセンスを記録し、NVDA 日本語版の対象バージョン・設定を固定して、同一文章の声、読み、速度を実聴比較し差を記録する。
8. 辞書、音声、WASM、前処理、ビルド依存物の配布条件と必要な権利表示・対応ソースの提供方法を確認する。未確認のものを含む構成は公開可能と判断しない。

## 8. 未決事項と公開前の条件

- **技術的な実現性**：目標音声データと候補エンジン・辞書の互換性、端末ごとの初期化時間、メモリ、合成時間、最大文章長および速度上限を実測する。
- **ライセンス**：配布物を確定し、各ライセンスと結合方法に応じた条件を確認する。NVDA 日本語版の拡張辞書には GPL-2.0-or-later の条件がある。プロジェクト自身のライセンスと必要なソース提供方法は未決定。
- **教材**：初期教材の数、題材、文章量を決め、著作権上利用可能な文章を用い、正解と解説を検証する。
- **対象環境**：具体的な OS・ブラウザ・バージョンは、PC とスマートフォンの実機検証に合わせて確定する。

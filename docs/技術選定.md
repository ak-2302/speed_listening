# 速聴トレーニング Web アプリ 技術選定

調査日：2026-10-23  
状態：提案。アプリや音声合成の実動作は未検証。

## 目的と前提

日本語テキストを音声にして速度を調整し、繰り返し聞く練習をブラウザ上で行う。対象は視覚障害のないユーザーを想定し、入力欄と再生操作を備えた GUI とする。通常のキーボード操作や読みやすさは確保する。トレーニングによる能力向上の効果は、この設計だけでは保証できない。

目標音声は、普及しているスクリーンリーダーの一つである **NVDA 日本語版の JTalk** とする。具体的な比較対象は NVDA 日本語版の JTalk「mei」音声とし、バージョン・辞書・音声設定を固定して検証する。「mei」が最も普及しているという統計は確認できていないため、比較用の暫定選択である。必要に応じて m001、lite、tohoku-f01 も選択肢とする。[NVDA 日本語版の説明](https://www-dev.nvda.jp/nvda2025.3.3jp/ja/readmejp.html)

スクリーンリーダーに共通の音声はない。WebAIM の 2026 年調査では、アジアの回答者が主に使用するデスクトップ用スクリーンリーダーは NVDA 77.4%、JAWS 17% だった。ただし任意回答の国際調査であり、日本の利用率や音声ごとのシェアを示すものではない。[調査結果](https://webaim.org/projects/screenreadersurvey11/)

本家 NVDA は Windows 10/11 で Windows OneCore を既定としている一方、日本語版には JTalk が含まれる。日本語版の説明では JTalk は Windows 7/8.1 の既定とされており、現行 Windows でも既定であるとは断定しない。[NV Access](https://www.nvaccess.org/get-help/)、[日本語版の説明](https://www-dev.nvda.jp/nvda2025.3.3jp/ja/readmejp.html)

**同じ声に加え、読みや速度の再現も目標とする。** 標準の Open JTalk と mei の組み合わせだけで NVDA の JTalk と同一になるとは限らない。NVDA 日本語版の拡張辞書、前処理、音声パラメータ、高速読み上げを含めて比較する。現時点ではブラウザでの再現性・ライセンス・音声一致は未検証である。

初期版は個人利用を想定し、ログイン、共有、サーバーへのテキスト送信、学習効果の測定は対象外とする。公開先やオフライン利用は未指定であり、以下は静的ホスティングを想定した暫定案である。

## 選定

| 領域 | 第一候補 | 理由・制約 |
| --- | --- | --- |
| GUI | React + TypeScript + Vite | 入力、合成、再生の状態を分離しやすく、静的配信できる。React は本リポジトリの指針に従う。 |
| 日本語音声 | NVDA 日本語版の JTalk の再現を目標に Open JTalk + HTS Engine の WebAssembly を検証。ラッパーは [openjtalkjs](https://github.com/keanu-thakalath/openjtalkjs) を暫定候補 | NVDA 版の辞書・前処理・音声設定の互換性は未確認。小規模なラッパーの保守性も含め、先に実機で検証する。 |
| 再生 | HTML `<audio>` + `playbackRate`、`preservesPitch` | 一時停止・再開・シークと再生中の速度変更を扱いやすい。音高を維持する設定を基本にする。ただし NVDA の高速読み上げとは別方式であり、一致を検証する。 |
| 実行分離 | openjtalkjs の Web Worker | 音声合成を UI スレッドから分離する。初期化失敗、生成中、再試行を表示する。 |
| 保存 | 初期版は設定のみ localStorage | 倍速等を端末内に保存。本文・音声・履歴は自動保存しない方針。 |
| 配信 | 静的ホスティング | アプリと辞書・音声・WASM を配信する。配信先の容量・転送量・利用条件は選定時に確認する。 |
| 検証 | Vitest、Playwright、実機ブラウザ | 状態・変換処理の単体検証と、実音声を含むブラウザ操作の検証を分ける。 |

Open JTalk 公式の最新版として掲載されている 1.11 は 2018 年公開で、エンジンは Modified BSD ライセンスである。辞書、HTS Engine、音声データやラッパーには別々の条件があるため、採用する各ファイルの配布元・バージョン・ライセンスと表示義務を確認し、公開時に第三者ライセンス一覧へ記載する。[Open JTalk 公式](https://open-jtalk.sourceforge.net/)

## 候補の比較

| 方式 | 利点 | 今回の判断 |
| --- | --- | --- |
| Open JTalk をブラウザ内で実行 | サーバー不要で本文をサーバーに送らずに済む。固定した辞書と声を配布できる。 | 第一候補。ただし辞書のサイズ、初回ロード、端末メモリ、WASM の配信と互換性を検証する。 |
| サーバーで Open JTalk を実行 | 標準的な実行環境を管理でき、端末ごとの差を抑えやすい。 | 代替案。サーバー維持費、本文の送信、同時実行制限や削除方針が必要。WASM が不適合なら再評価する。 |
| ブラウザ標準の SpeechSynthesis | 導入は容易。 | OS やブラウザの音声に依存し、JTalk を指定できないため採用しない。 |
| Open JTalk の解析 + 別の音声合成モデル | より自然な声を検討できる。 | 音声が JTalk の HTS 音声と異なるため初期版では採用しない。 |

## 参考リポジトリ

- [openjtalkjs](https://github.com/keanu-thakalath/openjtalkjs)：WASM、Worker、辞書・音声の指定、ブラウザからの非同期合成の構成を参考にする。README は PCM を int16 範囲の Float32Array と説明している。WAV 化時にスケールを誤らないよう対象バージョンで確認する。BSD-3-Clause 表記だが、同梱物は別途確認が必要。小規模なため更新状況とブラウザ対応を採用時に再確認する。
- [wasm_open_jtalk](https://github.com/hrhr49/wasm_open_jtalk)：Open JTalk の WASM ビルド方法の参考。README は Node.js の CLI 向けと明記しており、そのままブラウザ用として採用しない。最終更新・ライセンスとビルド環境を再確認する。
- [kokoro-js-jp](https://github.com/nerosui/kokoro-js-jp)：辞書の遅延ロード、Worker、実ブラウザ E2E の参考。Open JTalk は日本語解析に使い、音声は Kokoro が生成するため、JTalk 音声そのものの候補ではない。README は辞書を約 24 MB ダウンロードし約 107 MB に展開すると説明するが、本案の実測値ではない。Apache-2.0 とサードパーティ条件を確認する。

いずれも構成・テストの参考であり、コードや文章をコピーしない。依存バージョンを固定する前にリリース、更新状況、対応ブラウザ、配布物とライセンスを確認する。

## 操作と処理の流れ

1. ユーザーが日本語の文章を入力し、速度を選んで「音声を生成」を押す。
2. Worker が辞書・音声を読み込み、Open JTalk で PCM を生成する。UI に初期化・生成中・失敗を表示し、再試行を可能にする。
3. PCM をサンプルレートに従い WAV Blob に変換し、`<audio>` に渡す。オブジェクト URL は音声の差し替え・画面破棄時に解放する。
4. ユーザー操作で再生し、一時停止、再開、先頭へ戻る、シーク、速度変更、繰り返しを行う。本文変更後は生成済み音声が古いことを明示する。

空入力を拒否し、長文の上限は端末の実測後に設定する。生成中の重複要求は防ぎ、古い処理の結果が新しい入力を上書きしないよう要求 ID を管理する。辞書や音声の取得失敗、メモリ不足、再生拒否を通知する。合成中のキャンセルが必要なら Worker の停止・再初期化を検討する。

### 倍速の扱い

初期案は **1.0〜4.0 倍、0.1 刻み**、初期値 1.0 倍。これは要求値ではなく検証用の仮定。通常速度で合成した音声を `playbackRate` で再生し、`preservesPitch = true` を基本にする。合成自体の発話速度を変える方法とは間や音質が異なるため、必要なら別途比較する。ブラウザ・OS により高倍率の音質や再生可能範囲が異なり、4 倍までの実用性は未確認。上限は対象ブラウザで実音を聞いて決定する。[MDN playbackRate](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Audio_and_video_delivery/WebAudio_playbackRate_explained)、[MDN preservesPitch](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preservesPitch)

## 画面の方向性

- 対象・目的：画面を見ながら日本語の文章を速聴する個人ユーザー。主要操作は「文章を入力し、速度を選んで再生する」。
- 文章欄と再生操作を中心に、現在の倍率、再生位置、生成状態を近くに配置する。速聴に関係のない装飾や架空の成績表示は置かない。
- 倍率はスライダーだけに頼らず数値でも確認・変更できるようにする。狭い画面でも入力・再生・速度変更を使えるようにする。
- ラベル、フォーカス表示、色以外の状態表示を設ける。初回のデータ取得量、通信失敗、生成中、再生失敗を分かる形で示す。

## 配信・プライバシー

辞書、音声、WASM はアプリと同じ配信先に固定バージョンで置く案を優先する。初回にはそれらの取得が必要で、ブラウザキャッシュは削除・失効され得る。オフライン対応は Service Worker 等の実装と容量・更新検証を行うまでは保証しない。本文を外部へ送らない設計とし、分析ツールや外部サービスを追加する際は送信内容を再確認する。設定の localStorage は共有端末に残り、ブラウザデータの消去で失われる。

## 実装前の検証と決定事項

1. NVDA 日本語版の対象リリース、JTalk の mei 音声、拡張辞書、前処理、速さ・高さ・抑揚・高速読み上げ設定を固定する。まず実機で対象音声を取得し、比較基準を記録する。
2. [NVDA 日本語版の拡張辞書](https://github.com/nvdajp/nvdajp-jtalk-dic) と [JTalk 実装](https://github.com/nvdajp/python-jtalk) を調査し、音声・辞書・前処理をブラウザ候補と比較する。対象は Windows 向けの実装で、ブラウザへの移植は未検証。各コンポーネントのライセンス、ソース公開・表示等の条件、再配布の可否を個別に確認する。openjtalkjs を使う場合も同様。数字、記号、英字、固有名詞を含む文章で、読み、声、速度を実聴・長さ等で比較する。完全一致を宣言する基準は実装前に決める。
3. 対象のデスクトップとモバイルのブラウザで、初回ダウンロード量、初期化時間、メモリ、文章長ごとの合成時間、1〜4 倍の音質と操作性を実測する。利用端末・許容時間・最大文章長は未決定。
4. 再生中の速度変更、一時停止、シーク、反復、入力変更後の再生成、連続操作、取得失敗を検証する。自動再生制限に備えユーザー操作から再生し、`play()` の拒否を処理する。
5. ブラウザ移植が難しい場合、NVDA の対象実装を動かせる Windows 環境を使うサーバー・ローカル補助アプリを代替案として実証し、運用費、対応 OS、プライバシー、ライセンスを比較して再選定する。実現可能性は未検証。

上記は提案であり、現時点では動作、音声品質、ライセンス適合、実機性能を検証済みとして扱わない。
